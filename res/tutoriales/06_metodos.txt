# Tema 06: métodos (parámetros y retorno).
=== l06_tus_propios_metodos
tema: 06
orden: 1
titulo.es: Ponle nombre a tus maniobras
titulo.de: Gib deinen Manövern Namen
titulo.en: Give your manoeuvres names
--- pagina
es: Ya has escrito métodos sin darte cuenta: cadaTurno y alVerEnemigo lo son. Un método es un trozo de código
es: con nombre que puedes llamar cuando quieras. ¿Por qué molestarse? Porque cadaTurno empieza a ser una selva,
es: y «esquivar()» se entiende al primer vistazo, mientras que tres líneas de giros y avances hay que descifrarlas.
de: Du hast schon Methoden geschrieben, ohne es zu merken: jedenZug und beiSicht sind welche. Eine Methode ist
de: ein Stück Code mit Namen, das du jederzeit aufrufen kannst. Wozu? Weil jedenZug langsam zum Dschungel wird,
de: und „ausweichen()“ versteht man auf einen Blick, drei Zeilen Drehen und Fahren muss man erst entschlüsseln.
en: You've already written methods without noticing: onTick and onSeeEnemy are methods. A method is a named
en: piece of code you can call whenever you like. Why bother? Because onTick is turning into a jungle,
en: and "dodge()" makes sense at a glance, while three lines of turns and moves have to be deciphered.
codigo:
    void esquivar(double anguloDelGolpe) {
        girarHacia(anguloDelGolpe + 90);
        avanzar(150);
    }
    @Override
    public void alRecibirGolpe(Golpe g) {
        esquivar(g.angulo());
    }
--- pagina
es: La primera línea es la firma: void dice que no devuelve nada, esquivar es el nombre y entre paréntesis
es: van los parámetros, los datos que necesita. Al llamarlo, esquivar(g.angulo()), el valor viaja
es: al parámetro anguloDelGolpe. Un método va DENTRO de la clase pero FUERA de los demás métodos:
es: meter un método dentro de otro es un error de compilación muy frecuente al principio.
de: Die erste Zeile ist die Signatur: void heißt „gibt nichts zurück“, esquivar ist der Name, und in Klammern
de: stehen die Parameter, die Angaben, die sie braucht. Beim Aufruf esquivar(t.winkel()) wandert der Wert
de: in den Parameter. Eine Methode steht IN der Klasse, aber AUSSERHALB der anderen Methoden:
de: Eine Methode in eine andere zu schreiben ist am Anfang ein sehr häufiger Kompilierfehler.
en: The first line is the signature: void means it returns nothing, esquivar is the name and the parentheses
en: hold the parameters, the data it needs. When you call esquivar(h.angle()), the value travels into
en: the parameter. A method goes INSIDE the class but OUTSIDE the other methods:
en: putting a method inside another is a very common compile error at the start.
--- tarea
robot: ronda_sin_errores
es: Saca al menos una maniobra a su propio método (esquivar, buscar…) y pelea una ronda sin errores.
de: Lagere mindestens ein Manöver in eine eigene Methode aus (ausweichen, suchen …) und kämpf eine Runde
de: fehlerfrei.
en: Move at least one manoeuvre into its own method (dodge, search…) and fight a round without errors.

de: Eine Methode, die den Radius bekommt und die Fläche des runden Schilds zurückgibt.
en: A method that takes the radius and returns the area of the round shield.

=== l06_parametros_y_retorno
tema: 06
orden: 2
titulo.es: Preguntar y recibir respuesta
titulo.de: Fragen und Antwort bekommen
titulo.en: Asking and getting an answer
--- pagina
es: Un método puede devolver un resultado. En lugar de void pones el tipo que devuelve, y return entrega
es: el valor y termina el método. Así escribes preguntas con nombre: aTiro(e) se lee como una frase.
es: Si un método dice que devuelve boolean, TODOS sus caminos deben acabar en return; si no, Java protesta
es: con «missing return statement».
de: Eine Methode kann ein Ergebnis liefern. Statt void steht dann der Rückgabetyp, und return gibt den Wert
de: zurück und beendet die Methode. So schreibst du Fragen mit Namen: aTiro(g) liest sich wie ein Satz.
de: Verspricht eine Methode ein boolean, muss JEDER Weg in ihr bei einem return enden; sonst meckert Java
de: mit „missing return statement“.
en: A method can return a result. Instead of void you write the type it returns, and return hands back
en: the value and ends the method. That way you write questions with names: aTiro(e) reads like a sentence.
en: If a method says it returns a boolean, EVERY path through it must end in a return; otherwise Java
en: complains with "missing return statement".
codigo:
    boolean aTiro(Enemigo e) {
        return e.distancia() < alcanceDerecha();
    }
    double puntoMedio(double a, double b) {
        return (a + b) / 2;
    }
    @Override
    public void alVerEnemigo(Enemigo e) {
        apuntarHacia(e.angulo());
        if (aTiro(e)) {
            atacar();
        }
    }
--- pagina
es: Los parámetros reciben una COPIA del valor. Si dentro de un método haces distancia = 0,
es: la variable de quien lo llamó no cambia. Parece un detalle, pero evita sustos: un método no puede
es: estropearte tus números a escondidas. Si quieres un resultado nuevo, devuélvelo con return.
de: Parameter bekommen eine KOPIE des Werts. Setzt du in einer Methode distancia = 0,
de: ändert sich die Variable des Aufrufers nicht. Klingt nach Kleinkram, erspart aber Schrecken: Eine Methode
de: kann dir nicht heimlich deine Zahlen verderben. Willst du ein neues Ergebnis, gib es mit return zurück.
en: Parameters get a COPY of the value. If you set distance = 0 inside a method,
en: the caller's variable doesn't change. Sounds minor, but it saves nasty surprises: a method can't secretly
en: mess up your numbers. If you want a new result, return it.
--- pagina
es: Un buen método hace una sola cosa y su nombre lo dice. Si para explicar lo que hace necesitas un «y»
es: («apunta y además decide si huir»), seguramente son dos métodos. Y un truco: return a mitad de método
es: (una «salida rápida») te ahorra anidar ifs: if (!listoDerecha()) return; y el resto ya sabe que está listo.
de: Eine gute Methode tut genau eine Sache, und ihr Name sagt welche. Brauchst du zum Erklären ein „und“
de: („zielt und entscheidet außerdem, ob er flieht“), sind es wahrscheinlich zwei Methoden. Und ein Trick:
de: Ein return mitten in der Methode erspart verschachtelte ifs: if (!bereitRechts()) return; und der Rest
de: weiß Bescheid.
en: A good method does one thing and its name says what. If you need an "and" to explain it
en: ("aims and also decides whether to flee"), it's probably two methods. And a trick: a return halfway through
en: (an "early exit") saves you nesting ifs: if (!readyRight()) return; and the rest knows it's ready.

de: Entscheidungen.
en: Write your own method that returns something (with return) and use it in the robot's decisions for a round.

=== l06_sobrecarga
tema: 06
orden: 3
titulo.es: Mismo nombre, distintos datos
titulo.de: Gleicher Name, andere Daten
titulo.en: Same name, different data
--- pagina
es: Puedes tener dos métodos con el mismo nombre si sus parámetros son distintos: eso es la sobrecarga.
es: Java elige cuál llamar mirando lo que le pasas. Lo has usado ya: println(5) y println("hola")
es: son métodos distintos con el mismo nombre. El tipo de retorno solo no basta para distinguirlos.
de: Du darfst zwei Methoden mit gleichem Namen haben, wenn ihre Parameter verschieden sind: Das ist Überladen.
de: Java sucht anhand dessen, was du übergibst, die passende aus. Kennst du schon: println(5) und println("hallo")
de: sind verschiedene Methoden mit demselben Namen. Nur ein anderer Rückgabetyp reicht dafür nicht.
en: You can have two methods with the same name if their parameters differ: that's overloading.
en: Java picks which one to call by looking at what you pass. You've used it already: println(5) and
en: println("hi") are different methods with the same name. A different return type alone isn't enough.
codigo:
    void huir() {
        huir(150);                     // la versión corta llama a la larga
    }
    void huir(double distancia) {
        girar(180);
        avanzar(distancia);
    }
--- pagina
es: Con tres puntos (varargs) un método acepta tantos valores como quieras: double suma(double... golpes).
es: Dentro, golpes es un array (tema 7). Y los métodos static no necesitan un robot para funcionar:
es: Math.max es static, por eso lo llamas con el nombre de la clase. Los de tu robot (avanzar, girar)
es: no lo son: necesitan saber DE QUÉ robot hablas.
de: Mit drei Punkten (Varargs) nimmt eine Methode beliebig viele Werte an: double suma(double... treffer).
de: Darin ist treffer ein Array (Thema 7). Und static-Methoden brauchen keinen Roboter:
de: Math.max ist static, deshalb rufst du es über den Klassennamen auf. Die deines Roboters (vorwaerts, drehen)
de: sind es nicht: Sie müssen wissen, VON WELCHEM Roboter die Rede ist.
en: With three dots (varargs) a method accepts as many values as you like: double suma(double... hits).
en: Inside, hits is an array (topic 7). And static methods don't need a robot to work:
en: Math.max is static, which is why you call it with the class name. Your robot's methods (ahead, turn)
en: aren't: they need to know WHICH robot you mean.

en: Two ways to repair with the same name: write the overload.
