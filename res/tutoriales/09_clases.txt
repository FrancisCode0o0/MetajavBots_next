# Tema 09: clases y objetos.
=== l09_planos_y_robots
tema: 09
orden: 1
titulo.es: Planos y robots
titulo.de: Baupläne und Roboter
titulo.en: Blueprints and robots
--- pagina
es: Ha llegado el momento de entender la primera línea: public class MiRobot. Una clase es un PLANO:
es: describe qué datos tiene algo (sus campos) y qué sabe hacer (sus métodos). Un objeto es una cosa
es: construida con ese plano. Cuando empieza la pelea, la arena hace new MiRobot() y fabrica tu robot.
es: Con el mismo plano podría fabricar diez robots iguales, cada uno con sus propios campos.
de: Zeit, die erste Zeile zu verstehen: public class MiRobot. Eine Klasse ist ein BAUPLAN: Sie beschreibt,
de: welche Daten etwas hat (seine Felder) und was es kann (seine Methoden). Ein Objekt ist ein Ding, das
de: nach diesem Plan gebaut wurde. Beim Kampfstart macht die Arena new MiRobot() und baut deinen Roboter.
de: Mit demselben Plan könnte sie zehn gleiche Roboter bauen, jeder mit seinen eigenen Feldern.
en: Time to understand the first line: public class MiRobot. A class is a BLUEPRINT:
en: it describes what data something has (its fields) and what it can do (its methods). An object is a thing
en: built from that blueprint. When the fight starts, the arena does new MiRobot() and builds your robot.
en: From the same blueprint it could build ten identical robots, each with its own fields.
--- pagina
es: Por eso los campos sobreviven entre turnos: son del objeto, y el objeto vive toda la ronda.
es: Y por eso puedes llamar a avanzar() sin decir de quién: dentro de la clase, «yo» se sobreentiende.
es: Si quieres decirlo en voz alta, existe this: this.avanzar(50) es exactamente lo mismo.
de: Darum überleben Felder zwischen den Zügen: Sie gehören dem Objekt, und das Objekt lebt die ganze Runde.
de: Und darum kannst du vorwaerts() aufrufen, ohne zu sagen, wer: In der Klasse ist „ich“ selbstverständlich.
de: Willst du es aussprechen, gibt es this: this.vorwaerts(50) ist genau dasselbe.
en: That's why fields survive between turns: they belong to the object, and the object lives all round.
en: And that's why you can call ahead() without saying whose: inside the class, "me" is understood.
en: If you want to say it out loud, there's this: this.ahead(50) means exactly the same.

=== l09_tus_objetos
tema: 09
orden: 2
titulo.es: Tus propias piezas
titulo.de: Deine eigenen Bauteile
titulo.en: Your own parts
--- pagina
es: No todo tiene que vivir dentro de MiRobot. Puedes escribir clases pequeñas en el mismo archivo
es: (sin public delante) para agrupar datos que van juntos. Por ejemplo, un Avistamiento: dónde estaba
es: el enemigo, hacia dónde iba y en qué turno lo viste. Tres variables sueltas se pierden; un objeto no.
de: Nicht alles muss in MiRobot wohnen. Du kannst kleine Klassen in dieselbe Datei schreiben
de: (ohne public davor), um Daten zu bündeln, die zusammengehören. Zum Beispiel eine Sichtung: wo der Gegner war,
de: wohin er fuhr und in welchem Zug du ihn gesehen hast. Drei lose Variablen gehen verloren, ein Objekt nicht.
en: Not everything has to live inside MiRobot. You can write small classes in the same file
en: (without public in front) to bundle data that belongs together. For example a Sighting: where the enemy was,
en: where it was heading and on which turn you saw it. Three loose variables get lost; an object doesn't.
codigo:
    class Avistamiento {
        double x, y, rumbo, velocidad;
        int turno;
    }
--- pagina
es: Con new fabricas un objeto, y con el punto llegas a sus campos y métodos. Una variable de clase
es: no contiene el objeto, lo SEÑALA (como con los arrays). Si no señala a nada vale null, y usar
es: un null con el punto es la excepción más famosa de Java: NullPointerException. Antes de usarlo, pregunta.
de: Mit new baust du ein Objekt, und über den Punkt erreichst du seine Felder und Methoden. Eine Variable
de: mit Klassentyp enthält das Objekt nicht, sie ZEIGT darauf (wie bei Arrays). Zeigt sie auf nichts, ist sie null,
de: und null mit Punkt zu benutzen ist die berühmteste Ausnahme in Java: NullPointerException. Frag vorher nach.
en: With new you build an object, and the dot takes you to its fields and methods. A class-typed variable
en: doesn't hold the object, it POINTS to it (as with arrays). If it points to nothing it's null, and using
en: a null with the dot is Java's most famous exception: NullPointerException. Check before you use it.
codigo:
    Avistamiento ultimo = null;
    @Override
    public void alVerEnemigo(Enemigo e) {
        ultimo = new Avistamiento();
        ultimo.x = e.x();
        ultimo.y = e.y();
        ultimo.turno = turnoActual();
    }
    @Override
    public void cadaTurno() {
        if (ultimo != null && turnoActual() - ultimo.turno < 20) {
            apuntarA(ultimo.x, ultimo.y);
            atacar();
        } else {
            apuntar(25);
        }
    }
--- tarea
robot: usa:new
es: Guarda lo que ves en un objeto de una clase tuya (creado con new) y úsalo para apuntar durante una ronda.
de: Speichere, was du siehst, in einem Objekt einer eigenen Klasse (mit new erzeugt) und ziel eine Runde
de: lang damit.
en: Store what you see in an object of your own class (created with new) and aim with it for a round.

=== l09_constructores
tema: 09
orden: 3
titulo.es: Constructores y cosas de todos
titulo.de: Konstruktoren und gemeinsame Dinge
titulo.en: Constructors and shared things
--- pagina
es: Rellenar los campos uno a uno después del new es pesado y fácil de olvidar. Un constructor es un método
es: especial, con el nombre de la clase y sin tipo de retorno, que se ejecuta al hacer new. Así el objeto nace
es: completo: new Avistamiento(e, turnoActual()). Dentro, this.x = x distingue el campo del parámetro.
de: Die Felder nach dem new einzeln zu füllen ist mühsam und leicht vergessen. Ein Konstruktor ist eine besondere
de: Methode mit dem Namen der Klasse und ohne Rückgabetyp, die bei new läuft. So kommt das Objekt vollständig
de: zur Welt: new Avistamiento(g, zug()). Darin unterscheidet this.x = x das Feld vom Parameter.
en: Filling fields one by one after new is tedious and easy to forget. A constructor is a special method,
en: named like the class and with no return type, that runs on new. That way the object is born complete:
en: new Avistamiento(e, tick()). Inside, this.x = x tells the field apart from the parameter.
codigo:
    class Avistamiento {
        final double x, y;
        final int turno;
        Avistamiento(Enemigo e, int turno) {
            this.x = e.x();
            this.y = e.y();
            this.turno = turno;
        }
        @Override
        public String toString() {
            return "(" + (int) x + ", " + (int) y + ") en el turno " + turno;
        }
    }
--- pagina
es: Un campo static no es de cada objeto, sino de la clase entera: lo comparten todos.
es: Sirve para contadores globales (cuántos avistamientos llevas en total) y para constantes.
es: Ojo con abusar: un static que cambia es como una pizarra en un pasillo, cualquiera la toca.
de: Ein static-Feld gehört nicht jedem Objekt, sondern der ganzen Klasse: Alle teilen es.
de: Gut für globale Zähler (wie viele Sichtungen du insgesamt hattest) und für Konstanten.
de: Aber Vorsicht: Ein veränderliches static ist wie eine Tafel im Flur, jeder kritzelt darauf.
en: A static field doesn't belong to each object but to the whole class: they all share it.
en: It's good for global counters (how many sightings you've had in total) and for constants.
en: Don't overdo it: a static that changes is like a whiteboard in a corridor, anyone can scribble on it.
