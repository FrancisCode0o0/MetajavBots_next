titulo.de: While-Schleife

claves.de: while, while-schleife, while schleife, solange, wiederholen solange, kopfgesteuerte schleife
claves.en: while, while loop, what is a while loop, repeat while, loop until, as long as

es:
    Un bucle while repite un trozo de código una y otra vez mientras una condición sea verdad. Antes de cada vuelta pregunta «¿sigue siendo verdad?»; en cuanto la respuesta es no, sale y sigue con lo de abajo.
    Es el árbitro que cuenta en voz alta mientras el robot está en la lona: «uno, dos, tres…». Mientras el robot siga tumbado, cuenta otro número; en cuanto se levanta, se calla. Si el robot nunca se cae, el árbitro no cuenta ni uno.
    En Java se escribe while (condición) { … } y dentro va lo que se repite. Algo de dentro tiene que cambiar la condición, por ejemplo cuenta = cuenta - 1; o se repetiría para siempre. En el juego sirve para cálculos dentro de un turno: contar, buscar, ir partiendo una distancia.
    El fallo típico: esperar con un while a que el robot llegue a un sitio, como while (x() < 300) avanzar(10);. Dentro de un turno el robot no se mueve (se mueve entre turno y turno), así que x() nunca cambia y el bucle no acaba. Para «poco a poco» usa un if en cadaTurno: el propio juego repite cadaTurno.
de:
    Eine while-Schleife wiederholt ein Stück Code immer wieder, solange eine Bedingung wahr ist. Vor jeder Runde fragt sie „Stimmt das noch?“; sobald die Antwort Nein ist, hört sie auf und macht unten weiter.
    Sie ist der Ringrichter, der laut zählt, während der Roboter auf der Matte liegt: „eins, zwei, drei …“. Solange der Roboter liegen bleibt, zählt er weiter; steht er auf, verstummt der Richter. Geht der Roboter nie zu Boden, zählt er keine einzige Zahl.
    In Java schreibst du while (Bedingung) { … }, und hinein kommt, was sich wiederholt. Irgendetwas darin muss die Bedingung ändern, etwa zahl = zahl - 1;, sonst läuft es ewig. Im Spiel nimmst du sie für Rechnungen innerhalb eines Zugs: zählen, suchen, eine Strecke immer weiter halbieren.
    Der typische Fehler: mit einem while darauf warten, dass der Roboter irgendwo ankommt, etwa mit avanzar (vorwaerts): while (x() < 300) avanzar(10);. Innerhalb eines Zugs bewegt sich der Roboter nicht (er fährt erst zwischen den Zügen), also ändert sich x() nie und die Schleife endet nicht. Für „nach und nach“ nimm ein if in cadaTurno (jedenZug): Den wiederholt das Spiel sowieso.
en:
    A while loop repeats a piece of code again and again as long as a condition is true. Before every lap it asks "is it still true?"; as soon as the answer is no, it stops and carries on with what comes after.
    It is the referee counting out loud while the robot is down on the canvas: "one, two, three…". As long as the robot stays down, he says another number; the moment it gets up, he goes quiet. If the robot never falls, he doesn't count a single number.
    In Java you write while (condition) { … } with the repeated part inside. Something in there has to change the condition, for example count = count - 1;, or it would repeat forever. In the game it is for calculations within one tick: counting, searching, halving a distance again and again.
    The classic mistake: using a while to wait for the robot to reach a spot, like this one with avanzar (ahead): while (x() < 300) avanzar(10);. Within a tick the robot doesn't move (it moves between ticks), so x() never changes and the loop never ends. For "bit by bit", use an if in cadaTurno (onTick): the game repeats cadaTurno for you.

    MIENTRAS cuenta > 0:
        escribir cuenta
        cuenta ← cuenta - 1
    decir "¡Al ataque!"

    SOLANGE zahl > 0:
        schreibe zahl
        zahl ← zahl - 1
    sage "Angriff!"
pseudo.en:
    count ← 3
    WHILE count > 0:
        write count
        count ← count - 1
    say "Attack!"
ejemplo:
    public class MiRobot extends Metajavbot {
        @Override
        public void alEmpezar() {
            int cuenta = 3;
            while (cuenta > 0) {             // ¿aún quedan? otra vuelta || noch welche übrig? noch eine Runde || any left? one more lap
                escribir(cuenta + "...");
                cuenta = cuenta - 1;         // sin esto no acaba nunca || ohne das endet es nie || without this it never ends
            }
            decir("¡Al ataque!");
        }
    }

es:
    Un bucle for repite un trozo de código un número de veces que sabes de antemano: 3 veces, 10 veces, una vez por cada casilla. Lleva su propio contador, que va subiendo solo en cada vuelta.
    Es el entrenador del gimnasio del taller: «¡diez flexiones!». Empieza en la uno, cuenta cada una en voz alta y, al llegar a la diez, para. No hace falta que nadie le diga cuándo parar: lo sabía desde el principio.
    En Java: for (int i = 1; i <= 10; i++) { … }. Son tres partes separadas por punto y coma: dónde empieza el contador (int i = 1), hasta cuándo sigue (i <= 10) y cómo avanza (i++, sumar uno). En el juego sirve para repetir algo un número fijo de veces o recorrer un array con sus índices.
    El fallo típico: equivocarse en uno, el famoso «uno de más o de menos». for (int i = 0; i < 10; i++) da 10 vueltas (de 0 a 9) y con i <= 10 da 11. Decide si empiezas en 0 o en 1 y comprueba la última vuelta con un escribir(i).
de:
    Eine for-Schleife wiederholt ein Stück Code so oft, wie du vorher schon weißt: 3-mal, 10-mal, einmal pro Feld. Sie bringt ihren eigenen Zähler mit, der in jeder Runde von selbst hochzählt.
    Sie ist der Trainer im Werkstatt-Fitnessraum: „Zehn Liegestütze!“ Er fängt bei eins an, zählt jede laut mit und hört bei zehn auf. Niemand muss ihm sagen, wann Schluss ist: Das wusste er von Anfang an.
    In Java: for (int i = 1; i <= 10; i++) { … }. Drei Teile, getrennt durch Semikolons: wo der Zähler anfängt (int i = 1), wie lange es weitergeht (i <= 10) und wie er weiterzählt (i++, plus eins). Im Spiel wiederholst du damit etwas eine feste Anzahl von Malen oder läufst mit Indizes durch ein Array.
    Der typische Fehler: sich um eins verzählen, der berühmte „Off-by-one“. for (int i = 0; i < 10; i++) macht 10 Runden (0 bis 9), mit i <= 10 sind es 11. Entscheide, ob du bei 0 oder 1 anfängst, und prüf die letzte Runde mit escribir (ausgeben): escribir(i).
en:
    A for loop repeats a piece of code a number of times you know in advance: 3 times, 10 times, once per square. It carries its own counter, which goes up by itself on every lap.
    It is the coach in the workshop gym: "ten push-ups!". He starts at one, counts each one out loud and stops at ten. Nobody has to tell him when to stop: he knew from the very start.
    In Java: for (int i = 1; i <= 10; i++) { … }. Three parts separated by semicolons: where the counter starts (int i = 1), how long it keeps going (i <= 10) and how it moves on (i++, add one). In the game you use it to repeat something a fixed number of times or to walk through an array by index.
    The classic mistake: being off by one. for (int i = 0; i < 10; i++) does 10 laps (0 to 9), and with i <= 10 it does 11. Decide whether you start at 0 or 1, and check the last lap with escribir (print): escribir(i).

    sage "Aufwärmen erledigt"
pseudo.en:
    FOR i FROM 1 TO 3:
        write "push-up number " + i
    say "warm-up done"
ejemplo:

        @Override
        public void alEmpezar() {
            for (int i = 1; i <= 3; i++) {        // empieza en 1, sigue hasta 3, suma 1 || ab 1, bis 3, plus 1 || start at 1, up to 3, add 1
                escribir("flexión número " + i);
            }
            decir("calentamiento hecho");         // esto va después de las 3 vueltas || das kommt nach den 3 Runden || this comes after the 3 laps
        }
    }

titulo.es: Bucle do while

claves.de: do while, do-while, do-while-schleife, mindestens einmal, fußgesteuerte schleife, wiederholen bis
claves.en: do while, do-while, do-while loop, at least once, repeat until, run once then check
ver: while, for, azar
es:
    Un bucle do while es como un while, pero al revés: primero hace la vuelta y después pregunta si repite. Por eso se ejecuta siempre al menos una vez, aunque la condición sea falsa desde el principio.
    Es el robot que tira el dado de la suerte antes del combate: «tiro, y si no sale un seis, vuelvo a tirar». No tiene sentido preguntar «¿ha salido un seis?» antes de tirar la primera vez: hay que tirar sí o sí.
    En Java: do { … } while (condición); con la condición al final y un punto y coma detrás. Sirve cuando hay que hacer algo para saber si hay que repetirlo, como sacar un número con azar().nextInt(6) hasta que salga el que quieres.
    El fallo típico: olvidar el punto y coma final de while (…); o no cambiar nada dentro que haga falsa la condición. Y si puede pasar que no haga falta hacerlo ni una vez, no es un do while: usa un while normal.
de:
    Eine do-while-Schleife ist wie ein while, nur andersherum: Erst macht sie die Runde, dann fragt sie, ob sie wiederholt. Deshalb läuft sie immer mindestens einmal, selbst wenn die Bedingung von Anfang an falsch ist.
    Sie ist der Roboter, der vor dem Kampf den Glückswürfel wirft: „Ich werfe, und wenn keine Sechs kommt, werfe ich nochmal.“ Vor dem ersten Wurf zu fragen „Ist eine Sechs gefallen?“ ergibt keinen Sinn: Geworfen wird auf jeden Fall.
    In Java: do { … } while (Bedingung); mit der Bedingung am Ende und einem Semikolon dahinter. Du brauchst sie, wenn du erst etwas tun musst, um zu wissen, ob es wiederholt wird, etwa mit azar (zufall) eine Zahl ziehen, azar().nextInt(6), bis die gewünschte kommt.
    Der typische Fehler: das Semikolon nach while (…); vergessen oder darin nichts ändern, was die Bedingung falsch macht. Und wenn es sein kann, dass es gar nicht nötig ist, ist es kein do-while: Nimm ein normales while.
en:
    A do-while loop is like a while, but the other way round: it does the lap first and only then asks whether to repeat. That's why it always runs at least once, even if the condition is false from the start.
    It is the robot rolling the lucky die before the fight: "I roll, and if it isn't a six, I roll again". Asking "did I get a six?" before the first roll makes no sense: you have to roll no matter what.
    In Java: do { … } while (condition); with the condition at the end and a semicolon after it. Use it when you have to do something to find out whether to repeat it, like drawing a number with azar (random), azar().nextInt(6), until you get the one you want.
    The classic mistake: forgetting the semicolon after while (…); or not changing anything inside that makes the condition false. And if it may not be needed even once, it isn't a do-while: use a normal while.

    tiradas ← 0
    REPETIR:
        dado ← número al azar del 1 al 6
        tiradas ← tiradas + 1
    MIENTRAS dado ≠ 6
    escribir "seis en " + tiradas + " tiradas"
pseudo.de:
    wuerfe ← 0
    WIEDERHOLE:
        wuerfel ← Zufallszahl von 1 bis 6
        wuerfe ← wuerfe + 1
    SOLANGE wuerfel ≠ 6
    schreibe "Sechs nach " + wuerfe + " Würfen"
pseudo.en:
    rolls ← 0
    REPEAT:
        die ← random number from 1 to 6
        rolls ← rolls + 1
    WHILE die ≠ 6
    write "six after " + rolls + " rolls"
ejemplo:
    public class MiRobot extends Metajavbot {
        @Override
        public void alEmpezar() {
            int tiradas = 0;
            int dado;
            do {
                dado = azar().nextInt(6) + 1;        // un dado de 1 a 6 || ein Würfel von 1 bis 6 || a die from 1 to 6
                tiradas++;
            } while (dado != 6);                     // la pregunta va al final, con ; || die Frage steht am Ende, mit ; || the question goes last, with ;
            escribir("seis en " + tiradas + " tiradas");

    }

=== break_continue
nivel: 2
tema: 05
titulo.es: Break y continue
titulo.de: Break und continue
titulo.en: Break and continue
claves.es: break, continue, break y continue, salir del bucle, saltar una vuelta, romper el bucle, cortar el bucle
claves.de: break, continue, break und continue, schleife verlassen, schleife abbrechen, runde überspringen
claves.en: break, continue, break and continue, exit a loop, leave the loop, skip an iteration, skip to next
ver: for, while, anidar, switch
es:
    break y continue son dos palabras para cambiar la marcha de un bucle desde dentro. break sale del bucle en el acto; continue se salta lo que queda de esta vuelta y pasa a la siguiente.
    Imagina al robot repasando la fila de rivales en la arena: «este vuela, no me sirve, ¡siguiente!» (eso es continue). «Este está a tiro: le pego y dejo de mirar a los demás» (eso es break). Ni uno ni otro sale del ring: solo dejan la fila.
    En Java se escriben solos, con punto y coma: break; y continue;, casi siempre dentro de un if. En el juego van muy bien al recorrer enemigosVistos(): continue para descartar a los que no valen y break en cuanto has encontrado el que buscabas.
    El fallo típico: creer que break sale de todo. Solo sale del bucle (o del switch) más cercano: si hay un bucle dentro de otro, el de fuera sigue dando vueltas. Y un continue en un while antes de cambiar el contador deja el bucle atascado para siempre.
de:
    break und continue sind zwei Wörter, mit denen du den Lauf einer Schleife von innen änderst. break verlässt die Schleife sofort; continue überspringt den Rest dieser Runde und macht mit der nächsten weiter.
    Stell dir den Roboter vor, der die Reihe der Gegner in der Arena durchgeht: „Der fliegt, nützt mir nichts, nächster!“ (das ist continue). „Der ist in Reichweite: zuschlagen und die anderen gar nicht mehr anschauen“ (das ist break). Keins von beiden verlässt den Ring, nur die Reihe.
    In Java stehen sie allein mit Semikolon: break; und continue;, fast immer in einem if. Im Spiel passen sie prima beim Durchlaufen von enemigosVistos (gesehen): continue, um Unpassende auszusortieren, und break, sobald du den Gesuchten gefunden hast.
    Der typische Fehler: zu glauben, break verlasse alles. Es verlässt nur die nächste Schleife (oder das nächste switch): Steckt eine Schleife in einer anderen, dreht die äußere weiter. Und ein continue in einem while, bevor der Zähler geändert wird, lässt die Schleife ewig hängen.
en:
    break and continue are two words for changing how a loop runs from the inside. break leaves the loop on the spot; continue skips the rest of this lap and moves on to the next one.
    Picture the robot going down the line of rivals in the arena: "this one flies, no use to me, next!" (that's continue). "This one is in range: hit it and stop looking at the rest" (that's break). Neither leaves the ring, only the line.
    In Java they stand alone with a semicolon: break; and continue;, nearly always inside an if. In the game they fit nicely when walking through enemigosVistos (seenEnemies): continue to skip the ones that don't fit, and break as soon as you have found the one you wanted.
    The classic mistake: thinking break leaves everything. It only leaves the nearest loop (or switch): if one loop is inside another, the outer one keeps going. And a continue in a while before the counter changes leaves the loop stuck forever.

            apuntar y atacar
            SALIR DEL BUCLE (break)

        WENN gegner fliegt:
            NÄCHSTER (continue)
        WENN gegner näher als 80:
            zielen und angreifen

    FOR EACH rival I can see:
        IF rival flies:
            NEXT (continue)
        IF rival is closer than 80:

                if (e.distancia() < 80) {
                    apuntarHacia(e.angulo());
                    atacar();
                    break;                           // ya he pegado: fuera del bucle || schon zugeschlagen: raus aus der Schleife || already hit: out of the loop
                }
            }
        }
    }

=== bucle_infinito
nivel: 2
tema: 05
titulo.es: Bucle infinito
titulo.de: Endlosschleife
titulo.en: Infinite loop
claves.es: bucle infinito, while true, no termina nunca, se cuelga, tope de calculo, tope de pasos, se queda pensando
claves.de: endlosschleife, unendliche schleife, while true, hört nie auf, hängt sich auf, rechenlimit, denkt nach
claves.en: infinite loop, endless loop, while true, never ends, hangs, step limit, stalls thinking
ver: while, break_continue, turno, rendimiento
es:
    Un bucle infinito es un bucle cuya condición nunca se vuelve falsa: da vueltas y más vueltas y no acaba nunca. En un programa normal, el programa se queda colgado y no hace nada más.
    Es el locutor loco que se queda enganchado en «¡y golpea, y golpea, y golpea…!» mientras el combate sigue sin él. En MetajavBots el árbitro tiene un cronómetro: si tu robot no termina de pensar a tiempo, lo deja quieto unos turnos.
    El juego cuenta los pasos que da tu código (el tope de cálculo). Si cadaTurno se pasa, el robot «se queda pensando» y pierde turnos, más cuantas más veces te pases; la consola lo avisa con ⏱. A veces se escribe while (true) a propósito, pero siempre con un break dentro que lo corte.
    El fallo típico en el juego: esperar dentro de un turno algo que solo cambia entre turnos, como while (x() < 300) avanzar(10); o while (energia() < 50) {}. Mientras dura tu turno nada se mueve ni se recarga. Usa un if: «si aún no he llegado, avanzo un poco», y deja que el juego repita cadaTurno.
de:
    Eine Endlosschleife ist eine Schleife, deren Bedingung nie falsch wird: Sie dreht Runde um Runde und hört nie auf. Ein normales Programm hängt sich dabei auf und tut nichts anderes mehr.
    Sie ist der verrückte Kommentator, der bei „und er schlägt, und er schlägt, und er schlägt …“ hängen bleibt, während der Kampf ohne ihn weitergeht. In MetajavBots hat der Ringrichter eine Stoppuhr: Denkt dein Roboter nicht rechtzeitig zu Ende, lässt er ihn ein paar Züge stillstehen.
    Das Spiel zählt die Schritte deines Codes (das Rechenlimit). Überzieht cadaTurno (jedenZug), „denkt der Roboter nach“ und verliert Züge, umso mehr, je öfter du überziehst; die Konsole meldet es mit ⏱. Manchmal schreibt man absichtlich while (true), aber immer mit einem break darin, das es beendet.
    Der typische Fehler im Spiel: innerhalb eines Zugs auf etwas warten, das sich nur zwischen den Zügen ändert, etwa while (x() < 300) avanzar(10); oder while (energia() < 50) {} (avanzar und energia heißen auf Deutsch vorwaerts und energie). Während dein Zug läuft, bewegt und lädt sich nichts. Nimm ein if: „Wenn ich noch nicht da bin, fahre ich ein Stück“, und lass das Spiel cadaTurno wiederholen.
en:
    An infinite loop is a loop whose condition never turns false: it goes round and round and never ends. A normal program just hangs and does nothing else.
    It is the crazy commentator stuck on "and he hits, and he hits, and he hits…" while the fight carries on without him. In MetajavBots the referee has a stopwatch: if your robot doesn't finish thinking in time, he freezes it for a few ticks.
    The game counts the steps your code takes (the step limit). If cadaTurno (onTick) goes over, the robot "stalls thinking" and loses ticks, more the more often you go over; the console flags it with ⏱. Sometimes you write while (true) on purpose, but always with a break inside that ends it.
    The classic mistake in the game: waiting within a tick for something that only changes between ticks, like while (x() < 300) avanzar(10); or while (energia() < 50) {} (in English, avanzar is ahead and energia is energy). While your tick runs, nothing moves or recharges. Use an if: "if I'm not there yet, move a bit", and let the game repeat cadaTurno.
pseudo.es:
    CADA TURNO:
        SI aún no he llegado a 300:
            avanzar un poco
        (NO: MIENTRAS no he llegado, avanzar; en un turno no te mueves)
    MIENTRAS SIEMPRE:
        hacer algo
        SI ya está: SALIR (break)
pseudo.de:
    JEDEN ZUG:
        WENN ich noch nicht bei 300 bin:
            ein Stück fahren
        (NICHT: SOLANGE nicht angekommen, fahren; in einem Zug bewegst du dich nicht)
    SOLANGE IMMER:
        etwas tun
        WENN fertig: VERLASSEN (break)
pseudo.en:
    EVERY TICK:
        IF I haven't reached 300 yet:
            move a bit
        (NOT: WHILE not there, move; you don't move within a tick)
    WHILE FOREVER:
        do something
        IF done: LEAVE (break)
ejemplo:
    public class MiRobot extends Metajavbot {
        @Override
        public void cadaTurno() {
            if (x() < 300) {                    // un if, no un while: en un turno no te mueves || ein if, kein while: in einem Zug bewegst du dich nicht || an if, not a while: you don't move within a tick
                avanzar(10);
            }
            int n = 1;
            while (true) {                      // sin fin a propósito... || absichtlich endlos... || endless on purpose...
                n = n * 2;
                if (n > anchoArena()) break;    // ...pero con salida segura || ...aber mit sicherem Ausgang || ...but with a safe exit
            }
        }
    }

=== anidar
nivel: 2
tema: 05
titulo.es: Anidar
titulo.de: Verschachteln
titulo.en: Nesting
claves.es: anidar, anidado, anidados, bucles anidados, bucle dentro de otro, if dentro de if, nested
claves.de: verschachteln, verschachtelt, verschachtelte schleifen, schleife in schleife, if im if, nested
claves.en: nesting, nested, nested loops, loop inside a loop, if inside an if, nested if
ver: for, if_else, bloque, break_continue
es:
    Anidar es meter una cosa dentro de otra: un if dentro de un if, un bucle dentro de otro bucle, un if dentro de un bucle. Lo de dentro se hace entero cada vez que lo de fuera le da paso.
    Es como las muñecas rusas del taller: dentro del robot grande hay uno mediano, y dentro de ese, uno chiquitín que da los puñetazos. Con bucles: por cada vuelta del de fuera, el de dentro da todas las suyas, como un reloj con su aguja de horas y su aguja de minutos.
    En Java basta con escribir un bloque dentro del otro, con su sangría: for (int fila = 0; fila < 3; fila++) { for (int col = 0; col < 3; col++) { … } } recorre 3 × 3 = 9 casillas. En el juego es normal un if dentro del for que recorre enemigosVistos(), y otro if dentro para ver si el brazo está listo.
    El fallo típico: perderse en las llaves y cerrar donde no toca, o usar la misma letra i en los dos bucles. Usa nombres distintos (fila, col), cuida la sangría y, si hay más de tres niveles, saca la parte de dentro a un método propio.
