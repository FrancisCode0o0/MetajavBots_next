    Una excepción es el aviso de «algo ha salido mal» que Java lanza en plena ejecución: dividir un entero entre cero, pedir la posición 10 de un array de 5, usar algo que es null. Si nadie la atiende, ese trozo del programa se corta y Java enseña qué pasó y dónde.

    En Java una excepción es un objeto: ArithmeticException, ArrayIndexOutOfBoundsException, NullPointerException o la NumberFormatException de Integer.parseInt("hola"). Trae un mensaje (getMessage()) y la traza de la pila (printStackTrace()), la lista de métodos por los que pasó, del más reciente al más antiguo. es:
    try-catch es la red de seguridad de Java: en el bloque try pones lo que puede fallar y en el bloque catch, lo que hay que hacer si falla. Si no falla nada, el catch ni se mira.
    Imagina un robot trapecista haciendo el triple mortal sobre el ring: el try es el salto y el catch es la red que sujeta debajo el mecánico, con cara de resignación. Si cae, la red lo recoge y el espectáculo sigue; si no cae, la red se queda ahí, aburrida.
    Se escribe try { ... } catch (NumberFormatException e) { ... }: entre paréntesis va el tipo de excepción que atrapas y una variable para mirarla (e.getMessage()). Puedes poner varios catch, del más concreto al más general, o juntar tipos con | desde Java 7: catch (IllegalArgumentException | IllegalStateException e). En el robot, por ejemplo, envuelve el Double.parseDouble de un mensaje de alOirAlEquipo para que un texto raro de un compañero no te deje aturdido.
    El fallo típico es el catch vacío (catch (Exception e) {}): el error desaparece en silencio y luego nadie sabe por qué el robot hace cosas raras. Atrapa solo lo que sabes arreglar y, como poco, escríbelo con escribir(e.getMessage()). Y no uses try-catch para lo que se evita con un if: mirar antes que la lista no está vacía es mejor que atrapar la excepción después.

es:
    throw lanza tú mismo una excepción, a propósito, cuando descubres algo que no tiene sentido. throws (con s) va en la cabecera de un método y avisa de qué excepciones pueden salir de él sin que las atrape.
    throw es el robot que tira la toalla al centro del ring gritando «¡esto no puede ser!». throws es el cartel colgado en la puerta del taller: «Cuidado: este soldador a veces escupe chispas». El cartel no apaga las chispas; solo avisa a quien entra.
    Se escribe throw new IllegalArgumentException("velocidad imposible: " + v); y el método se corta ahí mismo, como con un return. En la cabecera: String leerPlano(String texto) throws IOException. Si llamas a un método que declara una excepción comprobada, o la atrapas con try-catch o la declaras tú también con throws. En tus clases del juego (una Rueda, un Arma) usa throw para negarte a recibir valores imposibles.
    Fallos típicos: confundir las dos palabras (throw lanza una; throws declara), olvidar el new (throw IllegalStateException(); no compila) y lanzar sin mensaje. Pon siempre en el mensaje qué valor era el malo: quien lea la consola te lo agradecerá.
de:
    Mit throw wirfst du selbst eine Ausnahme, mit Absicht, wenn du etwas Unsinniges entdeckst. throws (mit s) steht im Kopf einer Methode und kündigt an, welche Ausnahmen aus ihr herauskommen können, ohne dass sie sie fängt.
    throw ist der Roboter, der das Handtuch in die Ringmitte wirft und brüllt: „Das kann doch nicht sein!“ throws ist das Schild an der Werkstatttür: „Vorsicht, dieses Schweißgerät spuckt manchmal Funken.“ Das Schild löscht keine Funken, es warnt nur alle, die hereinkommen.
    Man schreibt throw new IllegalArgumentException("unmögliche Geschwindigkeit: " + v); und die Methode ist an dieser Stelle zu Ende, wie bei einem return. Im Methodenkopf: String leerPlano(String texto) throws IOException. Rufst du eine Methode auf, die eine geprüfte Ausnahme deklariert, musst du sie entweder mit try-catch fangen oder selbst mit throws weitermelden. In deinen eigenen Spielklassen (eine Rueda, eine Arma) lehnst du mit throw unmögliche Werte ab.
    Typische Fehler: die beiden Wörter verwechseln (throw wirft, throws deklariert), das new vergessen (throw IllegalStateException(); kompiliert nicht) und ohne Nachricht werfen. Schreib immer hinein, welcher Wert falsch war: Wer die Konsole liest, wird es dir danken.
en:

    throw is the robot hurling the towel into the middle of the ring and shouting “This cannot be!” throws is the sign on the workshop door: “Careful, this welder sometimes spits sparks.” The sign doesn't put out any sparks; it just warns whoever walks in.
    You write throw new IllegalArgumentException("impossible speed: " + v); and the method stops right there, like with a return. In the header: String leerPlano(String texto) throws IOException. If you call a method that declares a checked exception, you either catch it with try-catch or declare it yourself with throws. In your own game classes (a Rueda, an Arma) use throw to refuse impossible values.
    Classic mistakes: mixing up the two words (throw raises one, throws declares), forgetting the new (throw IllegalStateException(); does not compile), and throwing without a message. Always say which value was wrong: whoever reads the console will thank you.

    Una excepción propia es una clase de excepción que te inventas tú para un problema de tu programa que las de Java no nombran bien: PiezaRotaException, SinEnergiaException…
    Es como bordar tu propia bandera de auxilio: en vez de la toalla blanca de siempre, sacas una que dice «SE ME HA ROTO EL BRAZO IZQUIERDO Y ME DA VERGÜENZA». El árbitro entiende al instante qué pasa, y tu entrenador puede tener un plan solo para esa bandera.

=== finally

titulo.es: finally y recursos

claves.es: finally, bloque finally, try-with-resources, try con recursos, cerrar recursos, autocloseable, pase lo que pase
claves.de: finally, finally-block, try-with-resources, ressourcen schliessen, autocloseable, auf jeden fall ausführen
claves.en: finally, finally block, try-with-resources, close resources, autocloseable, always runs, cleanup code

es:
    finally es un bloque que va detrás de try (y de sus catch) y se ejecuta [[siempre]]: haya ido bien, haya saltado una excepción o se haya hecho un return. Sirve para recoger: cerrar, apagar, dejar las cosas como estaban.
    Es el robot barrendero del ring: gane quien gane, haya KO, empate o el locutor se haya desmayado de la emoción, al final sale y barre los tornillos. Nadie le aplaude, pero si un día no sale, en la pelea siguiente todos resbalan.
    Se escribe try { ... } catch (...) { ... } finally { ... }. Para lo que hay que cerrar (lectores, archivos, conexiones) existe desde Java 7 el try-with-resources: try (BufferedReader r = new BufferedReader(new StringReader(texto))) { ... } cierra r solo al salir, porque implementa AutoCloseable; admite varios recursos separados por ; y los cierra en orden inverso. En el robot puedes usar finally para escribir un resumen del turno aunque algo falle por el camino.
    Fallos típicos: poner un return dentro de finally (se traga la excepción y el return del try; no lo hagas nunca) y cerrar a mano en finally lo que try-with-resources cierra mejor. Si al cerrar también falla algo, try-with-resources guarda ese segundo error como «suprimido» (getSuppressed()) en vez de perder el primero.
de:
    finally ist ein Block nach try (und seinen catch-Blöcken), der [[immer]] ausgeführt wird: ob alles gut ging, eine Ausnahme flog oder ein return kam. Er ist zum Aufräumen da: schließen, abschalten, alles so hinterlassen, wie es war.
    Er ist der Kehrroboter des Rings: Egal, wer gewinnt, ob K. o., Unentschieden oder der Sprecher vor Aufregung in Ohnmacht fällt, am Ende kommt er raus und fegt die Schrauben zusammen. Keiner klatscht, aber wenn er einmal nicht kommt, rutschen beim nächsten Kampf alle aus.
    Man schreibt try { ... } catch (...) { ... } finally { ... }. Für Dinge, die geschlossen werden müssen (Leser, Dateien, Verbindungen), gibt es seit Java 7 try-with-resources: try (BufferedReader r = new BufferedReader(new StringReader(texto))) { ... } schließt r beim Verlassen von selbst, weil es AutoCloseable implementiert; mehrere Ressourcen trennst du mit ; und sie werden in umgekehrter Reihenfolge geschlossen. Beim Roboter kannst du mit finally eine Zugübersicht ausgeben, auch wenn unterwegs etwas schiefgeht.
    Typische Fehler: ein return in finally (es verschluckt die Ausnahme und das return aus try; niemals machen) und in finally von Hand schließen, was try-with-resources besser schließt. Schlägt auch das Schließen fehl, hebt try-with-resources diesen zweiten Fehler als „unterdrückt“ auf (getSuppressed()), statt den ersten zu verlieren.

    Un método recursivo es uno que se llama a sí mismo con una versión un poco más pequeña del problema, hasta llegar a una tan pequeña que se resuelve sin más: el caso base.
    Es la matrioska de robots: para saber cuántos robots hay dentro del robot gigante, abres la carcasa y le haces la misma pregunta al de dentro, que abre la suya y pregunta al siguiente… hasta llegar al robotito diminuto que no tiene nada dentro y contesta «solo yo: 1».
